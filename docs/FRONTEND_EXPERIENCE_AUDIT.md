# 前端体验复核：不能把测试全绿等同于体验完成

日期：2026-09-24（UTC+8）。复核基线：0.4.0 / `588a3092ea22f3963edbf597db01a4f054d040f2`。
修订版本：0.4.1。范围只包括前端、素材呈现、交互、可读性与浏览器验证，不修改内核、世界规则、MCP 参数或依赖版本。

## 1. 对上一轮完成判断的纠正

上一轮 80 项回归和素材演示证实了接口/资源/动作主链路，不能证明多角色、长文、慢请求、小屏、持续操作下的用户体验合格。
本轮先在未改动的 0.4.0 上保留截图和诊断输出，再修复实际复现的问题，最后运行同条件对照、完整回归和持续操作。不能只用新增测试数或一段顺利录像作为交付依据。

## 2. 已确认的问题及修复

| 编号 | 原版实际观察或复现 | 修复 |
|---|---|---|
| UX-01 | 首次 `/play/map` 503 后一直留在空白场景；错误藏在未显示的加入表单里，没有重试入口 | 独立的可见连接失败面板、明确文案和重连按钮；不靠再创建角色恢复 |
| UX-02 | 手机加入表单被仍在显示的世界发言气泡遮盖 | 表单/对话框/完成面板优先；隐藏覆盖它们的气泡，保留消息历史 |
| UX-03 | 六个角色同点时，画面把它们错开，但点击仍按原始同一点判定，最右角色点不到 | 精灵、焦点框、发言锚点和点击共用同一局部显示位置；不改变权威坐标 |
| UX-04 | 阅读历史时新增一条消息，内部滚动位置从 20 跳到 100 | 保留可见消息的 ID 和相对偏移；追加和补读更早消息均保持阅读位置 |
| UX-05 | 其他角色行动触发名单刷新，键盘焦点从角色按钮退回 BODY | 按角色 ID 保留按钮节点并保护焦点；双击路径另做回归 |
| UX-06 | 提交发言后关闭编辑器并打开帮助，迟到的提交回执会关闭新的帮助窗口 | 仅在原来的表单仍然存在且打开时关闭它，不碰后来打开的窗口 |
| UX-07 | 载入素材画廊后开启减少动态效果，走路动画仍继续；五次取样有三个不同画面 | 动态响应系统偏好变化，并同步暂停按钮状态；暂停保留当前帧 |

原版双击名单在额外对照中成功，因此没有把双击列为原版确认缺陷。它只是节点保留改动后需要继续通过的回归场景。

## 3. 同时做的可读性整理

多人同点只显示重点角色的完整名字和同点人数提示，避免一叠相同的截断名字。全部角色仍可在画面点选或名单中选择。

气泡先按完整文本测量，再逐字显示，避免文字增长时反复跳位置；小屏限制同时摆放数量，超出的现场发言有直接进入完整记录的入口。不改台词、作者、时间或过期语义。

角色名单设置独立高度上限，长名字和状态不挤在一行，避免多人进入后把对话记录挤到页面很下方。小屏首次跟随适当放大，保留用户之后主动选择的缩放。触控按钮和气泡字体加大。

这些是当前 2D 示例的体验修复，不把通用内核改成一个 UI 引擎。相机与素材仍不产生世界事实。

## 4. 验证方法

### 原版复现和截图

隔离启动原版 0.4.0，使用真实浏览器、六个合成身份和现有 HTTP 接口。保留初次连接错误、多人同点、小屏发言、加入表单、阅读历史截图，以及点击/晚回执/动态偏好的诊断。

`before-findings.json` 与 `before-extra-findings.json` 记录原版；其中角色 ID 都属于一次性合成测试身份，不含身份令牌。截图与对照仅说明这些具体场景，不声称视觉问题已经穷尽。

### 可复跑专项

```sh
node tests/experience_layout.test.mjs
python tools/check_frontend_experience.py --soak-seconds 120
```

专项包括：初始失败后手动重连、六个同点角色逐个点击、名单双击、多人长发言布局、手机表单遮挡、溢出消息入口、键盘焦点、历史追加/补读的阅读锚点、真实键盘输入不触发游戏移动、慢回执与新对话框、离线期间世界变化与恢复、不同视口及英文、无效素材、独立查看器、动态减少动画设置。

持续阶段使用七个角色、两个前端，轮流发言、移动、停止和交互，并切换相机与视口。只通过既有接口产生数据，不直接改数据库或向前端注入虚假世界结果。

### 本轮本地运行边界

先完成一轮 120 秒持续阶段，实际约 121 秒、52 个循环，无页面异常；这轮用于发现修复是否引入回退。最终代码另跑更长的 300 秒阶段，最终结果以机器可读记录为准。

手机为 320/390 宽视口，另有 768、1024、1920 宽布局；使用浏览器模拟，不是真机。它也不是 100 人并发压测，不用这些数字推导服务器成本或手机帧率。

## 5. 实际运行结果

| 阶段 | 专门持续阶段时长 | 循环数 | 页面异常 |
|---|---:|---:|---:|
| 第一轮修复验证 | 121.3 秒 | 52 | 0 |
| 较长完整验证 | 301.3 秒 | 129 | 0 |
| 最终显示改动后的再次验证 | 91.3 秒 | 39 | 0 |

这些时间只统计脚本内专门的持续操作阶段，不含异常复现、截图检查、其他浏览器套件，也不是在宣传已经做了数小时稳定性认证。

最终代码再次通过 81 项回归、相机检查和 8 组浏览器脚本。新增脚本还验证了长发言的完整文本入口、新记录提示按钮、阅读更早记录的锚点，以及减少动态效果变更后的实际画布像素不再变化。最终验证开始/结束时比对前端内容哈希，确认运行过程中没有修改受测代码。

修复前对照见 [原版记录](evidence/frontend-experience-before-2026-09-24.json)，各阶段和最终验证见 [完整记录](evidence/frontend-experience-2026-09-24.json)。本机独立查看器的 `/review/` 提供截图对照页；源码位于 [对照页](../examples/observer/review/index.html)。

## 6. 不标为完成的范围

还没有验证物理手机、Safari/WebKit、真实软键盘/输入法组合、数小时连续使用、完整屏幕阅读器与对比度标准；素材仍是验证用像素示例，不是最终美术逐帧验收。不会把 Chromium 的手机仿真写成真机通过。

本轮确认的是上述具体缺陷已经修复、当前示例流程有更充分的回归证据，不是宣布所有终端、所有场景和产品体验已经全部完成。真实模型宿主测试仍属于架构线程，不混进本线程验收范围。
