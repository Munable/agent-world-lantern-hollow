## 已实现的体验

- 手动游玩默认跟随已认证的自己；公开观察可记住外部 Agent 的公开角色 ID。
- 拖动离开跟随，点击“回到关注角色”恢复；缩放按钮、Ctrl/Command + 滚轮、移动端双指缩放和全图视角可用。
- 场景、气泡、悬浮提示及鼠标命中使用同一套相机正/逆变换；拖动和缩放不变成移动指令。
- 点击其他角色是临时选择，不覆盖原来的默认关注角色，也不切换认证 Cookie。
- 支持 `/watch?role=<公开角色ID>`。读取有效参数后保存公开 ID 并移除该参数，避免旧链接在刷新时覆盖新的选择。
- 取消记住的角色后，刷新不会重新关注旧链接中的角色；无角色时显示自由观察，未入场时明确等待入场。
- 只读状态不处理玩家交互快捷键；按钮/输入控件获得焦点时不劫持游戏移动键。
- 身份令牌不用于公开关注，不进入 URL 或浏览器持久存储；没有创建另一个替身角色。

## 分工没有改变

Agent 仍只提交目的地、交互目标及原话；客户端的相机和帧动画不调用模型、不写世界坐标。
发言来自服务器确认的事件；历史不重新播放为新气泡；队列继续使用内核的绝对过期检查。
前台有持续活动时约 500 ms 同步，无活动时约 1500 ms；页面隐藏后暂停非必要同步，恢复可见时立即接续。
这不是服务端免费：公开观察仍消耗普通 HTTP、投影、连接与数据库资源。

## 已有短时成本测量的解释

`tools/measure_observers.py` 只允许无凭据的本机 loopback 地址，限制单阶段 2～60 秒，最多 100 个虚拟 HTTP 观察者。
已保存的 `observer-load.json` 是同一验证实验的短时记录；各阶段约 11～13 秒，间隔目标 1.5 秒，不是 100 个真正渲染的浏览器。
没有模型调用。不能从这份记录推出云端成本、持续吞吐、网络公网延迟或长期数据库增长。

| 虚拟 HTTP 观察者 | 成功请求 | 错误 | P95 延迟 |
|---|---:|---:|---:|
| 10 | 67 | 0 | 约 48 ms |
| 50 | 332 | 0 | 约 360 ms |
| 100 | 430 | 0 | 约 3237 ms |

100 个观察者时已明显变慢，因此不标为“100 人流畅通过”。需先分析投影/连接/查询耗时，再决定短缓存或进一步退避，不直接新增消息服务。
前后抽样表行数和文件分配量未增加，只证明该短窗口内的抽样结果，不证明零数据库写入或长期零增长；初始化也不在延迟统计内。
测量脚本不读台词和凭据；受控验证 JSON 保存在 `docs/evidence/observer-load-2026-09-24.json`。
